# Android Dev Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Everly off Expo Go onto a sideloadable Android dev build so the `everly-alarm` native module actually compiles and runs — exact alarms, full-song foreground-service playback, and Stop/Snooze/Done from the notification.

**Architecture:** `npx expo prebuild` generates a real `android/` project from `app.json`, which compiles the existing 776 lines of Kotlin in `modules/everly-alarm` and applies the app's own `AndroidManifest.xml` permissions. React Native keeps every screen; Kotlin stays a thin scheduling + playback helper. After the build gate, native becomes the authority on *when* a recurring alarm next fires, and JS stops independently recomputing it.

**Tech Stack:** Expo SDK 58, React Native 0.88, `expo-dev-client`, Kotlin + Expo Modules API, Android AlarmManager + `mediaPlayback` foreground service, JUnit for pure-Kotlin logic, jest-expo for JS.

**Spec:** `plans/android_alarm_reminder_native.md`, extended by the 13-section requirements doc in the originating conversation. Acceptance criteria from that doc are reproduced under Global Constraints so this plan is self-contained.

---

## Global Constraints

- Every screen stays in React Native; Kotlin is scheduling + playback only.
- All reminder times display in 12-hour format with a visible AM/PM selector; 12:00 AM and 12:00 PM must be distinguishable.
- No account, no internet, no backend. Scheduling and local audio playback work offline.
- Distribution is a sideloaded APK. Google Play policy constraints do not apply.
- Editing, disabling, or deleting a reminder cancels its pending alarms before scheduling replacements — no duplicate or orphaned alarms.
- Missed occurrences are shown as missed. Multiple old alarms are never auto-played on launch.
- Overlapping reminders never produce two simultaneous music tracks.
- Missing audio falls back to a bundled tone and surfaces a warning.
- Never promise to override Do Not Disturb or every device audio setting.
- A force-stopped app is not guaranteed to fire; say so rather than implying otherwise.
- Target the Android version on the test device (Pixel_6_Pro emulator, plus the user's physical phone).

## Review Focus

Input classes the spec implies that no task's happy path exercises. Each has a test pinned to its owning task.

1. **An alarm set for 12:00 AM or 12:00 PM** — the classic 12-hour conversion bug; must fire at midnight/noon, not 12 hours off. (Task 6)
2. **A weekly alarm whose only selected weekday is today, fired just now** — next occurrence is 7 days out, not today or tomorrow. (Task 6)
3. **An alarm past its `endDate`** — must stop scheduling rather than ring forever. (Task 7)
4. **Device rebooted while an alarm was mid-ring** — must restore the future schedule without replaying the interrupted alarm. (Task 9)
5. **Two alarms due in the same minute** — exactly one plays audio; the other is queued, visible, and individually dismissible. (Task 10)
